# Phase 8A: isolated automatic Core policy

`decideAutoRendering(text, context)` in `src/core/auto-policy.ts` returns an
`AutoRenderDecision`, extending the existing `RenderDecision` with
`lineLevel: false`. It is not imported by production content code. Existing
`analyzeText()` and `decideRendering()` remain the unchanged compatibility APIs.
There is no persisted policy setting or new user-facing mode.

## Evidence and rule ordering

Confidence labels are conservative engineering gates, **not calibrated
probabilities or measured accuracy claims**. Rules run in this order:

1. **Unsafe or unknown context → low/no-op.** `structurallySafe` must be exactly
   `true` and `editable` exactly `false`. These facts must come from the caller's
   structural checks; text evidence cannot override them.
2. **Empty/whitespace → low/no-op.** No strong-RTL default is used.
3. **Existing real-code classifier → high/LTR technical correction.** Reuse
   `isLikelyRealCodeText()` unchanged, including shell commands and source with
   Persian/Arabic strings or comments. Technical decisions never request inline
   isolation or line restructuring.
4. **Unsupported letter scripts → low/no-op.** Letter evidence uses Unicode
   letters intersected with the existing RTL/LTR character expressions. Numbers,
   punctuation, marks and Persian joiners do not vote for direction. Words may
   contain combining marks/joiners; a substantive word has at least two letters
   in one recognized direction and no letters in the other.
5. **Only URL/path/filename tokens → medium/LTR technical correction.** Each
   whitespace-separated token must be an `http(s)://` or `www.` URL, contain a
   slash/backslash with following non-whitespace text, or have a simple
   letter/number/underscore/hyphen filename plus an ASCII alphanumeric extension.
   These tokens are not counted as proof of a natural-language sentence.
6. **Fewer than four recognized letters → low/no-op.** This includes bare
   Persian/Arabic digits, unlike compatibility's broad RTL character test.
7. **Unclassified code-like syntax → medium at most.** If the classifier did
   not identify real code but braces, brackets, `; = < > | &` remain, do not
   permit structural wrapping. Ordinary sentence punctuation does not trigger
   this cap.
8. **High prose confidence** requires at least 12 letters in the base direction
   and three substantive words. Latin-only prose can qualify. Mixed prose
   qualifies only when its first recognized letter is RTL and RTL letters
   outnumber Latin letters by at least 2:1 (inclusive). English-first mixed
   prose never gets forced RTL, even with a long RTL tail.
9. **Remaining supported text → medium.** Single-direction text gets that
   direction; ambiguous mixed text gets `auto` with start alignment and
   `plaintext`, not a forced RTL direction.

## Correction boundaries

- High: `mode: full`. Prose gets reversible block direction/alignment/plaintext;
  RTL inline isolation is allowed only with explicit `allowInlineIsolation:
  true` and an existing inline-LTR match. Real code gets LTR/left/isolate only.
- Medium: `mode: minimal`, no inline isolation, no line wrapping.
- Low/unsafe: `mode: none`, direction `auto`, alignment `start`, bidi `normal`,
  no wrapping. A future consumer must skip rendering, not write these defaults.
- All auto results set `lineLevel: false`; this phase never authorizes line
  segmentation. Existing caller budgets must still constrain future rendering.

## Limitations and integration boundary

The 4/12-letter, three-word and 2:1 thresholds are explicit conservative
guardrails, not a language detector. Long paths/English terms can downgrade
otherwise readable RTL prose; short headings, unsupported scripts and mixed
directives may be skipped or get only minimal correction. The unchanged code
classifier retains its existing false-positive/false-negative limitations.
First-script and dominance evidence cannot prove intended clause ordering.

This policy does not inspect DOM, validate the caller's safety claims, or decide
page access. Future integration must honor `mode: none`/`minimal` and
`lineLevel: false`; the existing renderer currently receives independent
line-level options and must not be wired to auto decisions without that review.
Production ChatGPT/Claude and composer behavior remain on compatibility policy.
